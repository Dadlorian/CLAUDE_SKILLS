# OSPF Design and Deployment Guide

## Network Size Assessment

### Single Area (Area 0 only)
- **Network Size:** Up to 50 routers
- **Topology:** Simple, flat structure
- **SPF Calculation:** Minimal
- **LSA Flooding:** Immediate
- **Best for:** Small campus networks

### Multi-Area Design
- **Network Size:** 50-500 routers
- **Topology:** Hierarchical with backbone
- **SPF Calculation:** Per-area
- **LSA Flooding:** Area-limited
- **Best for:** Large campus, multi-building

### Large-Scale Multi-Area
- **Network Size:** 500+ routers
- **Topology:** Regional areas with central backbone
- **Stubby Areas:** Reduce LSA flooding
- **NSSA Areas:** Connect other protocols
- **Best for:** Enterprise wide-area

## Area Design Decisions

### Area 0 (Backbone)
- **Requirement:** All areas must connect to backbone
- **Size:** Keep moderately sized (10-20 routers typical)
- **ABRs:** 2-3 for redundancy
- **Routers:** Core routers plus distribution layer

### Standard Areas
- **Size:** 20-100 routers per area
- **ABRs:** 2 per area minimum
- **ASBR:** Within area if redistributing
- **Internal routers:** Majority of routers

### Stub Areas
- **Use Case:** Leaf areas with single ABR exit
- **LSAs:** No Type-5 external routes
- **Default Route:** Automatic from ABR
- **Risk:** Single ABR creates bottleneck

### Totally Stubby Areas
- **Use Case:** Branch office networks
- **LSAs:** No Type-3 (summary) or Type-5 (external)
- **Minimum Filtering:** Maximum LSA reduction
- **Limitation:** Cisco proprietary

### NSSA Areas
- **Use Case:** Connect external routing domains
- **Type-7 LSAs:** Generated by ASBR within area
- **Type-5 Conversion:** ABR converts to Type-5
- **Advantage:** Reduces flooding of Type-5 LSAs

## OSPF Metrics and Cost

### Cost Calculation Strategy

```
Default bandwidth = 100 Mbps
Interface cost = 100,000,000 / bandwidth (bps)

Examples:
- 1 Gbps = 1 (matches 100 Mbps = 1 on older devices)
- 100 Mbps = 1
- 10 Mbps = 10
- 1 Mbps = 100

Issue: All fast links (>100 Mbps) cost 1
Solution: Adjust reference-bandwidth
```

### Reference Bandwidth Adjustment
```
router ospf 1
  auto-cost reference-bandwidth 10000  ! 10 Gbps

Results:
- 10 Gbps = 1
- 1 Gbps = 10
- 100 Mbps = 100
- 10 Mbps = 1000
```

### Manual Cost Override
```
interface GigabitEthernet0/0
  ip ospf cost 50  ! Override calculated cost
```

## OSPF Priority and DR Election

### Default Behavior
- **Highest Router ID:** Becomes DR
- **Tiebreaker:** MAC address (if same priority)
- **Risk:** Non-optimal DR election

### Forced DR/BDR Election
```
! Primary DR (priority 150)
interface FastEthernet0/1
  ip ospf priority 150

! Backup DR (priority 100)
interface FastEthernet0/1
  ip ospf priority 100

! Non-participating (disable election)
interface FastEthernet0/1
  ip ospf priority 0
```

## Network Type Considerations

### Broadcast Networks (LANs)
- **Default:** Auto-detect on Ethernet
- **Behavior:** DR/BDR elected
- **Timers:** Hello 10s, Dead 40s
- **LSAs:** Type-2 (network) generated by DR

### Point-to-Point
- **Default:** Serial interfaces
- **Behavior:** No DR/BDR needed
- **Timers:** Hello 10s, Dead 40s
- **Advantage:** Reduced overhead

### Point-to-Multipoint
- **Use Case:** Hub-and-spoke, FR clouds
- **No DR:** Eliminates unnecessary election
- **Timers:** Hello 30s, Dead 120s
- **Flooding:** More efficient for spokes

### NBMA (Non-Broadcast Multi-Access)
- **Use Case:** Frame Relay, X.25
- **DR/BDR:** Required
- **Timers:** Hello 30s, Dead 120s
- **Challenge:** Neighbor must be statically configured

## Convergence Optimization

### SPF Timer Tuning
```
router ospf 1
  timers throttle spf 50 200 5000
  ! Delay, Hold Time, Maximum Hold Time
```

Explanation:
- **50ms:** Initial SPF delay
- **200ms:** Minimum hold between SPF runs
- **5000ms:** Maximum hold time (5 seconds)

### Fast Hellos
```
interface GigabitEthernet0/1
  ip ospf hello-interval 3
  ip ospf dead-interval 12
  ! Faster detection, more overhead
```

### BFD for Sub-Second Detection
```
interface GigabitEthernet0/1
  ip ospf bfd  ! Implicit BFD
  ! Or explicit:
  bfd interval 300 min_rx 300 multiplier 3

! Integrate with OSPF
router ospf 1
  ! BFD auto-detected on interfaces
```

## Virtual Link Design

### Use Cases
1. **Non-contiguous Backbone:** Connect via transit area
2. **Temporary Topology Change:** During network restructuring
3. **Worst Case:** Last resort (indicates poor design)

### Configuration
```
router ospf 1
  area 0 virtual-link 10.0.0.2 authentication-key PASS
  ! Router ID of far-end ABR

! Timers (same as area 0)
area 0 virtual-link 10.0.0.2 hello-interval 10 dead-interval 40
```

### Design Issues
- Virtual links are area 0 paths
- Cannot use stub areas as transit
- Performance degraded vs direct links

## Authentication Implementation

### Area-Wide Authentication
```
router ospf 1
  area 0 authentication message-digest
  ! All routers in area 0 must use MD5

interface GigabitEthernet0/1
  ip ospf message-digest-key 1 md5 MYPASSWORD
```

### Per-Interface Authentication
```
interface GigabitEthernet0/1
  ip ospf authentication message-digest
  ip ospf message-digest-key 1 md5 MYPASSWORD
```

### SHA-256 Authentication (OSPF for IPv6)
```
interface GigabitEthernet0/1
  ipv6 ospf authentication ipsec spi 1000 sha1 HEXKEY
```

## Summarization Strategy

### Inter-Area Summarization (ABR)
```
router ospf 1
  area 0 range 10.1.0.0 255.255.0.0
  area 0 range 10.2.0.0 255.255.0.0
  ! Reduces LSA type-3 flooding
```

### External Route Summarization (ASBR)
```
router ospf 1
  summary-address 192.168.0.0 255.255.0.0
  ! Reduces type-5 LSA flooding
```

### Best Practices
- Summarize at area boundaries (ABR)
- Summarize external routes (ASBR)
- Use contiguous address space
- Avoid overlapping summaries

## Default Route Origination

### Originate Default Route
```
router ospf 1
  default-information originate metric 100 metric-type 2

! Only if default exists in routing table
router ospf 1
  default-information originate metric 100 metric-type 2

! Always originate (even without default)
router ospf 1
  default-information originate always metric 100
```

### External Type 1 vs Type 2
- **Type 1:** Cost = external cost + internal cost
- **Type 2:** Cost = external cost only (default)

## Redistribution Points

### Single Redistribution Point
```
! Central ASBR
router ospf 1
  redistribute bgp 65000 metric 100 metric-type 2
  redistribute static metric 100 metric-type 2
```

### Multiple ASBRs
```
! ASBR1 & ASBR2 redistribute same routes
! Use forwarding address to prefer shorter path
router ospf 1
  redistribute bgp 65000 metric 100
  ! Lowest metric wins
```

## Deployment Checklist

### Pre-Deployment
- [ ] Document network topology and subnets
- [ ] Assign area numbers and router IDs
- [ ] Plan metric strategy (reference bandwidth)
- [ ] Define summarization boundaries
- [ ] Plan DR/BDR placement
- [ ] Identify critical links for BFD

### Configuration
- [ ] Configure loopback interfaces (router IDs)
- [ ] Enable OSPF and assign areas
- [ ] Configure network statements or interface commands
- [ ] Set DR priority on broadcast links
- [ ] Configure summarization
- [ ] Configure authentication
- [ ] Implement BFD for critical links
- [ ] Configure default-information originate

### Verification
- [ ] Verify neighbor formation: `show ip ospf neighbors`
- [ ] Check DR/BDR election: `show ip ospf interface`
- [ ] Verify OSPF database: `show ip ospf database`
- [ ] Check routing table: `show ip route ospf`
- [ ] Monitor LSA flooding: `debug ip ospf flooding`
- [ ] Test failover scenarios

### Monitoring
- [ ] Track topology changes
- [ ] Monitor SPF calculation times
- [ ] Alert on neighbor state changes
- [ ] Monitor OSPF database size
- [ ] Track redistribution changes

## Common Pitfalls and Solutions

| Issue | Cause | Solution |
|-------|-------|----------|
| Neighbors not forming | Network type mismatch | Set `ip ospf network` explicitly |
| Suboptimal paths | Default cost on high-speed | Use `auto-cost reference-bandwidth` |
| High convergence time | Default SPF timers | Tune `timers throttle spf` |
| Excessive LSA flooding | No summarization | Implement inter-area and external summarization |
| DR/BDR instability | Network instability | Increase hello/dead timers, use BFD |
| Memory bloat | Large LSDB | Use stub/totally stuby areas, summarize |

## Best Practices Summary

1. **Design for scalability:** Use multi-area for networks >50 routers
2. **Optimize metrics:** Use reference-bandwidth for fast links
3. **Control flooding:** Summarize at area and external boundaries
4. **Fast convergence:** Tune SPF timers and use BFD
5. **Secure deployment:** Use MD5/SHA authentication
6. **Monitor actively:** Track neighbors, LSA counts, and convergence
7. **Plan carefully:** Document topology before deployment
8. **Test thoroughly:** Validate neighbor formation and routes before production
