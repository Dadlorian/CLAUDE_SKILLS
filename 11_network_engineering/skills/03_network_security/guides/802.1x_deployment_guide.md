# 802.1X Deployment Guide

## Planning and Preparation

### Step 1: Assessment and Requirements

```
Current State:
- Existing network access controls
- Current authentication method (if any)
- Wireless security current state
- Wired port security current state
- Users/devices to be authenticated
- Support structure available

Requirements:
- Numbers of users/devices
- BYOD support needed?
- Guest access needed?
- Application criticality
- Compliance requirements
- Timeline and budget
- Acceptable downtime
```

### Step 2: PKI Setup (for EAP-TLS)

```
Build Internal Certificate Authority:

On Windows Server:
1. Install Active Directory Certificate Services
2. Configure Enterprise Root CA
3. Create certificate templates
4. Configure auto-enrollment

On Linux:
1. Install OpenSSL or cfssl
2. Create root certificate
3. Configure intermediate CA
4. Create server certificate template

Server Certificate (for RADIUS):
- CN: radius.example.com
- Subject Alt Name: radius.example.com, 192.168.100.1
- Key size: RSA 2048+ or ECDSA P-256
- Validity: 3 years
- Install on RADIUS server
```

### Step 3: RADIUS Server Deployment

```
Windows NPS (Network Policy Server):

Installation:
1. Add role: Network Policy and Access Services
2. Configure: Network Policy Server
3. Add RADIUS clients (switches/APs)
4. Configure authentication policies
5. Create user/group access policies

Linux FreeRADIUS:

Installation:
apt-get install freeradius freeradius-utils

Configuration:
1. Configure clients.conf (switches)
2. Configure users file (authentication)
3. Configure authorize file (policies)
4. Configure radiusd.conf (server settings)
5. Test with radtest

Configuration Example:
/etc/freeradius/3.0/clients.conf:
client Building-A-Switch {
    ipaddr = 10.0.0.5
    secret = SuperSecretKey123!
    shortname = building-a-switch
}

Test:
radtest testuser testpassword 127.0.0.1 10 testing123
```

### Step 4: Choose EAP Method

```
Recommendation Matrix:

Small/Medium Organization + Windows-heavy:
→ PEAP with EAP-MSCHAPv2 (Most compatible)

Large Organization + Mixed Platforms:
→ EAP-TLS (Strongest security)

Cost-Sensitive + Acceptable Risk:
→ PEAP with EAP-MSCHAPv2

Modern Security-First Organization:
→ EAP-TLS or WPA3-Enterprise

Timeline:
- 1-2 weeks: PEAP setup
- 2-4 weeks: EAP-TLS setup (requires PKI)
- Security value: EAP-TLS > PEAP >> Others
```

## Switch Configuration

### Cisco Switch 802.1X Setup

```
Enable AAA/Authentication:

aaa new-model
aaa authentication dot1x default group radius
aaa authorization network default group radius
aaa accounting dot1x default start-stop group radius

Configure RADIUS Server:
radius server RADIUS_PRIMARY
 address ipv4 10.1.100.10 auth-port 1812 acct-port 1813
 key 0 SuperSecretKey123!

Enable 802.1X:
dot1x system-auth-control

Configure Interface:
interface GigabitEthernet0/0/1
 description User Port - 802.1X Enabled
 dot1x pae authenticator
 dot1x port-control auto
 dot1x reauthentication enable
 dot1x timeout reauth-period 3600
 dot1x timeout tx-period 30
 dot1x timeout quiet-period 60
 dot1x timeout supp-timeout 30
 authentication host-mode single-host

Optional - Guest VLAN (users who don't auth):
dot1x guest-vlan 999

Optional - Fallback (for non-compliant devices):
authentication fallback FALLBACK_ACL

Verify:
show dot1x interface GigabitEthernet0/0/1
show dot1x statistics interface GigabitEthernet0/0/1
show authentication sessions interface GigabitEthernet0/0/1
```

### Fortinet FortiSwitch 802.1X Setup

```
Enable 802.1X:
config switch-controller managed-switch
 edit FSW-IFM
  set override-ip 10.1.100.1
  config ports
   edit port1
    set native-vlan 1
    set allowed-vlans 1-4094
    set 802-1x enable
    set 802-1x-port-mode multi-secure
   next
  end
 next
end

Configure RADIUS:
config user radius
 edit RADIUS_SERVER
  set server 10.1.100.10
  set secret SuperSecretKey123!
  set timeout 5
  set retransmit 3
  set port 1812
  set accounting-server 10.1.100.10
  set accounting-port 1813
 next
end

VLAN Assignment via RADIUS:
# Configure tunnel attributes in RADIUS server
Tunnel-Type = VLAN (13)
Tunnel-Medium-Type = IEEE-802 (6)
Tunnel-Private-Group-ID = 100
```

## Access Point (WiFi) Configuration

### Cisco Wireless Controller 802.1X

```
Configure WLAN with 802.1X:

Access Controller Web UI:
1. WLANs menu
2. Create new WLAN
3. Profile name: Corporate-802.1X
4. SSID: Corporate-Secure
5. Security tab
   - Layer 2 Security: WPA2 Enterprise
   - Authentication Key Mgmt: WPA2
   - 802.1X Authentication: Enable
   - RADIUS servers: Add RADIUS server
   - Key Refresh Interval: 3600

Server Configuration:
interface GigabitEthernet0/0/0
 ip address 10.1.100.1 255.255.255.0

radius server RADIUS_PRIMARY
 address ipv4 10.1.100.10 auth-port 1812 acct-port 1813
 key 0 SuperSecretKey123!

Verification:
show wlan summary
show ap dot1x statistics <AP_name>
show 802-11 syslog aps <AP_name>
```

### WPA3-Enterprise (Modern Standard)

```
Configuration:

Access Point Setup:
1. SSID: Corporate-Secure
2. Security: WPA3-Enterprise
3. EAP Method: EAP-TLS or PEAP
4. RADIUS Server: 10.1.100.10:1812
5. RADIUS Secret: SuperSecretKey123!

Advantages:
- Latest security standard
- Better protection against weak passwords
- Individualized Data Encryption (IDe)
- Opportunistic Wireless Encryption (OWE)
- Protection against brute force

Client Support:
- Windows 11
- macOS Ventura+
- iOS 16+
- Android 13+
- Linux (with WPA_supplicant updates)

Gradual Rollout:
Phase 1: WPA2/WPA3 transition (90 days)
Phase 2: WPA3-only for critical networks (90 days)
Phase 3: WPA3-Enterprise as default
```

## Client Configuration

### Windows Configuration

```
Group Policy Configuration (AD):

1. Create GPO: 802.1X-Policy
2. Computer Configuration
   → Policies
   → Windows Settings
   → Security Settings
   → 802.1X Configuration
3. Edit:
   - Enable 802.1X
   - EAP Type: Protected EAP (PEAP)
   - Select PEAP/MSCHAPv2
   - Configure PEAP
   → Validate Server Certificate: Enable
   → Select Root CA certificate
   → Select Client Authentication Method: MSCHAPv2
   → Remember credentials: No (more secure)

Apply to Computers OU:
- Link GPO to appropriate OU
- Apply to user computers

Manual Configuration:
Settings → Network & Internet → WiFi
→ Manage Known Networks → Add
→ Network name: Corporate-Secure
→ Connect Automatically: Yes
→ Connect even if not broadcasting: No
→ Security Type: WPA3-Enterprise
→ Encryption Type: CCMP
→ User Info: Domain username/password
```

### macOS Configuration

```
WiFi Preferences:
1. System Preferences → Network → WiFi
2. Advanced → WiFi tab
3. Add network: Corporate-Secure
4. Security: WPA3 Enterprise
5. User Authentication:
   - Username: domain\username
   - Password: xxxxxxxx
6. Trust on First Use (TOFU) certificate acceptance

Network Preferences:
→ Advanced → 802.1X tab
→ EAP Profile: PEAP
→ Inner Authentication: MSCHAPv2
→ Trusted Certificates: CA cert
```

### Linux Configuration

```
WPA Supplicant Configuration:

/etc/wpa_supplicant/wpa_supplicant.conf:
ctrl_interface=/run/wpa_supplicant
network={
    ssid="Corporate-Secure"
    key_mgmt=WPA-EAP
    eap=PEAP
    identity="username@example.com"
    password="password"
    ca_cert="/etc/ssl/certs/ca-bundle.crt"
    phase1="peapver=0"
    phase2="auth=MSCHAPV2"
}

Start Service:
sudo systemctl start wpa_supplicant
sudo systemctl enable wpa_supplicant

Verify Connection:
iwconfig
ip addr show wlan0
ping default-gateway
```

## Deployment Rollout

### Phase 1: Pilot (Week 1-2)

```
Scope: Single department (25-50 users)

Activities:
- Configure switches/APs
- Configure RADIUS
- Roll out to pilot group
- Provide support
- Gather feedback
- Troubleshoot issues
- Document solutions

Success Criteria:
- 95%+ successful auth
- Support issues manageable
- No production impact
- Performance acceptable
```

### Phase 2: Soft Rollout (Week 3-6)

```
Scope: Department expansion (100-200 users)

Parallel Access:
- Keep existing open SSID available
- Both 802.1X and open available
- Users can switch during transition

Activities:
- Configure additional APs/ports
- Migrate users from open
- Support troubleshooting
- Handle exceptions

Timeline:
- Week 3-4: First half of users
- Week 5-6: Remaining users
- Keep open SSID available for fallback
```

### Phase 3: Full Deployment (Week 7+)

```
Scope: Organization-wide

Timing:
- Phase 3A (Week 7-8): Corporate networks
- Phase 3B (Week 9-10): Branch offices
- Phase 3C (Week 11-12): Remote offices

Final Steps:
- Disable open SSID (if migration complete)
- Monitor authentication failures
- Handle late adopters
- Final documentation
- Staff training completion
```

## Monitoring and Troubleshooting

### Key Metrics

```
Track:
- Authentication success rate (target: >99%)
- Average auth time (<2 seconds)
- Failed auth attempts
- RADIUS server response time
- Certificate expiration dates
- User adoption rate

Monitor:
show authentication sessions detail
show dot1x interface
show radius server statistics
```

### Common Issues

```
Issue 1: Authentication Failures
Diagnosis:
- Check RADIUS connectivity
- Verify credentials
- Check certificate validity
- Review RADIUS logs

Solution:
- Verify RADIUS server running
- Test with radtest utility
- Confirm password correct
- Renew expired certificates

Issue 2: Slow Authentication
Diagnosis:
- Check RADIUS response time
- Monitor network latency
- Check EAP configuration
- Verify certificate chain

Solution:
- Add additional RADIUS servers
- Optimize network path
- Use faster EAP method
- Simplify certificate chain

Issue 3: Device Won't Authenticate
Diagnosis:
- Check device 802.1X support
- Verify WPA2/WPA3 support
- Check EAP method support
- Review device logs

Solution:
- Update device drivers
- Check OS version support
- Use compatible EAP method
- Provide guest VLAN fallback
```

## Troubleshooting Guide

### Authentication Debug Log Example

```
802.1X Authentication Sequence:

Device → Switch: EAPOL Start
Switch → RADIUS: EAP Request/Identity
RADIUS → Switch: Forward to server
...
Server → RADIUS: EAP Success
RADIUS → Switch: Forward success
Switch → Device: EAP Success
Device: Authenticates
Switch: Authorizes port
Device: Gets IP address
Device: Connected
```

### RADIUS Debug Output

```
FreeRADIUS Debug:
radiusd -X

Output indicates:
- Client authentication accepted/rejected
- EAP method exchange
- RADIUS client information
- Authorization results

Look for issues:
- "Unknown client" - Client IP not configured
- "Bad password" - Credential mismatch
- "Unknown EAP" - EAP method not configured
- "Certificate expired" - Renew certificate
```
