# Medical Device Software Skill

## Overview

Expert-level knowledge in regulatory-compliant medical device software development. This skill covers the complete lifecycle from concept through FDA/CE approval, including IEC 62304 software development processes, Software as a Medical Device (SaMD) classification, risk management per ISO 14971, security controls, validation testing, and post-market surveillance. Essential for developers building life-critical healthcare software.

## Common Challenges and Solutions

### Challenge: Agile Development vs. Waterfall Regulations
**Solution**: Implement "agile within the gates" approach. Use iterative development with clear phase gates (requirements, design, verification). Accept regulatory artifacts may lag development slightly.

### Challenge: Test Coverage in Legacy Code
**Solution**: Implement regression testing for existing code. Focus new tests on changes. Use code analysis tools to identify high-risk untested paths. Plan refactoring as separate controlled activity.

### Challenge: Machine Learning Model Validation
**Solution**: Comprehensive dataset documentation. Multiple validation approaches (cross-validation, holdout sets, real-world data). Continuous performance monitoring. Version control all training code and data.

### Challenge: Managing Third-Party Components
**Solution**: Formal supplier qualification. Vulnerability scanning of dependencies. Software Bill of Materials (SBOM) generation. Traceability of components through entire supply chain.

### Challenge: Cybersecurity in Legacy Systems
**Solution**: Threat modeling even for legacy systems. Security patches within change control process. Consider air-gapped operation if network isolation is infeasible. Document security assumptions.

### Challenge: Demonstrating Equivalence to Predicate Devices
**Solution**: Detailed predicate device characterization. Side-by-side feature comparison. Test protocols demonstrating equivalent performance. Clinical judgment about meaningful differences.

### Challenge: User Training and Competency
**Solution**: Comprehensive training program documentation. Competency assessment before unsupervised use. Periodic retraining. Leverage design controls feedback to improve training.

### Challenge: Post-Market Surveillance with Limited Data
**Solution**: Automated monitoring systems capturing performance metrics. User complaint database with root cause analysis. Proactive outreach to facilities for feedback. Regular trend analysis.

## Workflow Patterns

### Traditional FDA 510(k) Workflow
1. Product Concept → Predicate Device Identification
2. Risk Assessment → 21 CFR 820.30 Design Controls
3. Software Development → IEC 62304 Compliance
4. Verification & Validation → Comprehensive Test Evidence
5. Risk Management Report → ISO 14971 Completion
6. Cybersecurity Assessment → FDA Guidance Compliance
7. 510(k) Submission Preparation → Regulatory Documentation
8. FDA Review Period (30-90 days) → Respond to Deficiency Letters
9. Clearance → Establish Post-Market Surveillance
10. Post-Market Monitoring → Complaint Handling and Analysis

## Success Criteria

You have mastered medical device software development when you can:

- Design and implement a complete IEC 62304 software development process
- Conduct ISO 14971 risk analysis with meaningful hazard identification
- Prepare and submit a regulatory-grade 510(k) or PMA application
- Develop comprehensive verification and validation plans with risk-based testing
- Implement secure software development with threat modeling and controls
- Navigate FDA feedback and deficiency letters effectively
- Establish post-market surveillance systems
- Mentor team members on regulatory compliance requirements
- Make trade-off decisions between agility and compliance
- Anticipate regulatory questions and proactively address them
