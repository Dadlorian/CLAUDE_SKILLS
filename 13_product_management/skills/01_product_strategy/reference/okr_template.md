# OKR Templates & Examples

## OKR Structure

```
OBJECTIVE: [Qualitative, inspiring description of what we want to achieve]

Key Result 1: [Quantitative measure - specific metric and target]
Key Result 2: [Quantitative measure - specific metric and target]
Key Result 3: [Quantitative measure - specific metric and target]
```

---

## Template 1: Growth-Focused OKR

### Use When: Scaling user base or market presence

```
OBJECTIVE: Establish Slack as the communication standard for mid-market companies

Key Result 1: Increase monthly recurring revenue from $50M to $75M
Key Result 2: Grow daily active users from 2.5M to 4M
Key Result 3: Achieve 35% expansion revenue (upsells from existing customers)
```

**Metrics to consider:**
- Revenue (total, recurring, growth %)
- New customers acquired
- Market share
- Geographic expansion
- User growth
- Expansion revenue from existing accounts

---

## Template 2: Retention & Engagement OKR

### Use When: Fighting churn or increasing product adoption

```
OBJECTIVE: Deepen product engagement and reduce customer churn

Key Result 1: Reduce monthly churn rate from 8% to 5% for existing customers
Key Result 2: Increase average daily active users per account from 60% to 80%
Key Result 3: Launch adoption program reaching 80% of new customers within first 30 days
```

**Metrics to consider:**
- Churn rate
- Retention cohorts (30-day, 90-day, annual)
- Daily/weekly active users
- Features adopted per customer
- Customer health score
- Net Retention Rate (NRR)

## Common OKR Pitfalls to Avoid

### Pitfall 1: Output vs Outcome

**Bad (Output-focused):**
```
OBJECTIVE: Launch premium product
Key Result 1: Build premium dashboard
Key Result 2: Write documentation
Key Result 3: Train sales team
```
❌ These are activities, not outcomes

**Good (Outcome-focused):**
```
OBJECTIVE: Establish premium offering generating significant new revenue
Key Result 1: Launch premium tier achieving $1M MRR
Key Result 2: Achieve 30% of new enterprise customers on premium
Key Result 3: Demonstrate 3x margin on premium vs standard
```
✓ These measure what changed

---

### Pitfall 2: Too Many Key Results

**Bad:**
```
OBJECTIVE: Grow the business
Key Result 1: Acquire 5,000 new customers
Key Result 2: Expand to 3 new countries
Key Result 3: Increase retention by 10 points
Key Result 4: Launch new feature
Key Result 5: Improve performance by 50%
Key Result 6: Hire 20 people
Key Result 7: Improve NPS by 8 points
```
❌ This is 7 OKRs disguised as key results

**Good:**
```
OBJECTIVE: Grow the business
Key Result 1: Increase annual recurring revenue from $50M to $75M
Key Result 2: Improve net retention rate from 110% to 125%
Key Result 3: Expand to 3 new geographic markets with product-market fit
```
✓ 3 key results, each measures different dimension of growth

---

### Pitfall 3: Metric Confusion

**Bad:**
```
Key Result 1: Grow pageviews 100%
Key Result 2: Increase engagement
Key Result 3: Improve conversion rates
```
❌ Vague, no specific targets, confusing what's being measured

**Good:**
```
Key Result 1: Increase monthly active users from 2.5M to 4M
Key Result 2: Improve daily active user % from 45% to 65%
Key Result 3: Improve enterprise conversion rate from 8% to 12%
```
✓ Specific, measurable, clear baseline and target

---

### Pitfall 4: Sandbagging (Under-committing)

**Problem:** Setting OKRs you're 95%+ confident in achieving (no stretch)

**Why it's bad:**
- No motivation to push beyond status quo
- Organization doesn't build ambitious capability
- Investors/board see minimal progress

**Healthy OKR confidence:** 60-70%
- This requires pushing beyond current trajectory
- Most will be achieved, but some will miss (that's OK!)
- Forces prioritization and hard choices

**Example:**
```
Current state: 100K users, 10% growth/month

Bad OKR (sandbagging):
Key Result: Reach 150K users (47.5% growth - easy trajectory)
Confidence: 95%

Good OKR (stretch):
Key Result: Reach 250K users (150% growth - requires new motion)
Confidence: 65%
```

---

### Pitfall 5: Circular Dependencies

**Problem:** Multiple teams' OKRs depend on each other (blockers)

**Example:**
```
Team A OKR: Launch new product achieving $1M MRR
  - Depends on: Design system from Team B (not committed yet)

Team B OKR: Build design system
  - Depends on: Requirements from Team A (not finalized)
```

❌ Both teams blocked

**Solution:**
- Identify dependencies during planning
- Ensure dependent team's OKR includes this work
- Create clear handoff milestones
- Re-plan if critical dependencies emerge

## OKR Levels & Alignment

### Company OKRs
```
Highest level - what the entire company is trying to achieve

OBJECTIVE: Establish as leader in AI-powered analytics

Key Result 1: Achieve $100M ARR
Key Result 2: Win 3 Fortune 100 customers using AI features
Key Result 3: Achieve NPS of 65
```

### Department/Team OKRs
```
One level down - how teams contribute to company OKRs

PRODUCT TEAM OBJECTIVE: Deliver AI features customers love
Key Result 1: Launch AI recommendations affecting 80% of customer workflows
Key Result 2: Achieve 40% adoption of AI features
Key Result 3: Improve NPS for AI features to 70

ENGINEERING TEAM OBJECTIVE: Build scalable, reliable AI infrastructure
Key Result 1: Reduce model inference latency 60%
Key Result 2: Achieve 99.95% uptime on AI services
Key Result 3: Support 10x current usage volume
```

### Individual OKRs (Optional)
```
Individual contribution to team OKRs - not recommended unless supporting company OKRs
Usually 2-3 OKRs aligned to team goals
Should be individual contribution, not just repeating team OKRs
```

### Alignment Check
```
Company OKR: Achieve $100M ARR

Team OKRs should support:
✓ Product team: Build features customers pay for
✓ Sales team: Close enterprise deals
✓ Marketing team: Generate qualified leads
✓ Customer Success: Reduce churn, expand accounts
✓ Finance: Improve unit economics

Bad: Team OKRs completely orthogonal to revenue goal
```

## OKR Confidence & Grading

### Confidence Levels During Planning

**When setting OKRs, ask: "If everything goes well, how likely are we to achieve this?"**

- **80-100% confidence:** Sandbagging - not ambitious enough
- **60-75% confidence:** Ideal - ambitious but achievable
- **40-60% confidence:** Risky - requires all things going well
- **0-40% confidence:** Moonshot - perhaps separate from normal OKRs

### Grading at End of Period

**Score each Key Result:**
- **1.0:** Achieved 100%+ of target
- **0.7-0.9:** Achieved 70-99% of target
- **0.4-0.7:** Achieved 40-69% of target (partial success)
- **0.0:** Achieved <40% of target (miss)

**Interpretation:**
- **Average score 0.7+:** Good quarter, OKRs were well-calibrated
- **Average score 0.8-0.9:** Great quarter, OKRs might have been too conservative
- **Average score <0.6:** Missed too many, either OKRs too ambitious OR execution issues

**Example Grading:**

```
OBJECTIVE: Establish as #1 in customer satisfaction
Key Result 1: Achieve NPS of 70 [Actual: 68] → Score: 0.9
Key Result 2: Reduce churn to 3% [Actual: 4%] → Score: 0.6
Key Result 3: Win Best Service award [Achieved] → Score: 1.0

Average Score: 0.83 → Good execution, slight miss on churn
```

## OKR Meeting Cadence

### Planning
- **Monthly OKRs:** Set in last week of prior month
- **Quarterly OKRs:** Set in last 2 weeks of prior quarter
- **Annual OKRs:** Set in November/December for next year

### Check-ins
- **Monthly OKRs:** Weekly progress review
- **Quarterly OKRs:** Bi-weekly progress review (CFRs - Conversations, Feedback, Recognition)
- **Annual OKRs:** Monthly progress review

### Review & Retrospective
- **Monthly OKRs:** Review in last week of month (5 min per team)
- **Quarterly OKRs:** Review in first week of new quarter (1-2 hours)
- **Annual OKRs:** Comprehensive review in Q4 planning (2-4 hours)

## OKR Communication Template

### When sharing OKRs with organization:

```
TEAM: Product

OBJECTIVE: Make AI features delightful and valuable to customers
Why: AI is key differentiator and growth driver. Early feedback shows excitement but adoption low.

Key Result 1: 50% of power users actively use AI features weekly
- Why: Usage is signal of real value vs toy
- How we'll measure: Weekly active feature usage from analytics
- Current state: 20% usage, so 2.5x growth needed

Key Result 2: Achieve 75 NPS for customers using AI features vs 65 overall
- Why: Want to ensure we're building what customers love
- How we'll measure: Post-feature survey of AI feature users
- Current state: 68 baseline NPS

Key Result 3: Reduce time-to-value on first use from 15min to 5min
- Why: Fast value drives adoption
- How we'll measure: Onboarding flow analytics
- Current state: 15 min avg, want to cut by 2/3

What we're NOT doing: Building 10 new AI features
- Trade-off: Going deep on 3 critical features vs shallow on 10
```

## Quick OKR Templates by Company Stage

### Early Stage (Seed-Series A)
```
OBJECTIVE: Find product-market fit in [market segment]
Key Result 1: Achieve 90%+ user retention after month 1 (sign of strong fit)
Key Result 2: Generate $X MRR from product (survival)
Key Result 3: Get testimonials from 10 customers showing clear value

OBJECTIVE: Build team and product foundation
Key Result 1: Hire [#] engineers with [specific skills]
Key Result 2: Implement [core technical capability]
Key Result 3: Reduce onboarding time from X to Y days
```

### Growth Stage (Series B-C)
```
OBJECTIVE: Expand to new customer segments while deepening existing
Key Result 1: Grow ARR from $X to $Y (specific revenue target)
Key Result 2: Achieve [metric] with new segment Z (PMF in new segment)
Key Result 3: Improve NRR from X% to Y% (expansion revenue)

OBJECTIVE: Build competitive moat
Key Result 1: Launch features X, Y, Z creating switching costs
Key Result 2: Achieve [market position] vs competitors
Key Result 3: Build [capability] that takes competitors 2+ years to match
```

### Scale Stage (Series D+)
```
OBJECTIVE: Establish category leadership
Key Result 1: Achieve [market share]% vs competitors
Key Result 2: Become top-3 rated on [review platforms]
Key Result 3: Achieve profitability at [margin]%

OBJECTIVE: Expand adjacent markets
Key Result 1: Launch [adjacent product] achieving [metrics]
Key Result 2: Achieve [% of revenue] from new products (portfolio balance)
Key Result 3: Enter [number] new geographic markets
```
