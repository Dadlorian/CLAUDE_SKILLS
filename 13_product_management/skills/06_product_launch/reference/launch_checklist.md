# Comprehensive Pre-Launch Checklist

## 8-Week Pre-Launch Planning & Execution

This checklist covers all phases of a Tier 1/2 launch. Adjust items based on your launch tier (Tier 3 launches require minimal items).

---

## WEEK 1: Launch Strategy & Alignment

### Launch Foundation
- [ ] Define launch tier (Tier 1, 2, or 3)
- [ ] Identify launch sponsor (executive owner)
- [ ] Establish launch team and roles
- [ ] Set launch date and lock timeline
- [ ] Define target launch audience and segments
- [ ] Identify primary go-to-market channels

### Success Metrics & Goals
- [ ] Define success metrics (adoption, revenue, NPS, etc.)
- [ ] Set specific, measurable targets for each metric
- [ ] Establish baseline metrics (pre-launch comparison)
- [ ] Create measurement dashboard
- [ ] Define Day 1, Week 1, Week 4, and Week 8 goals
- [ ] Identify North Star metric impact

### Stakeholder Alignment
- [ ] Schedule stakeholder alignment meeting
- [ ] Brief executive leadership team
- [ ] Get approval on launch plan and resources
- [ ] Confirm cross-functional team availability
- [ ] Establish weekly launch sync cadence
- [ ] Document launch goals and constraints

### Competitive & Market Analysis
- [ ] Analyze competitive landscape (5-10 competitors)
- [ ] Identify competitive threats or responses
- [ ] Assess market positioning vs. competitors
- [ ] Document competitive advantages
- [ ] Identify counter-arguments or concerns
- [ ] Plan competitive response if needed

### Internal Communication Plan
- [ ] Create launch communication template
- [ ] Plan internal announcements schedule
- [ ] Brief all teams on launch goals and timeline
- [ ] Set up internal launch Slack channel
- [ ] Schedule team training/briefing sessions
- [ ] Establish escalation and decision-making process

---

## WEEK 2: Messaging & Positioning

### Value Proposition Development
- [ ] Draft problem statement (what problem does this solve?)
- [ ] Define solution (how does your product solve it?)
- [ ] Identify core benefits (3-5 key benefits)
- [ ] Document differentiators vs. alternatives
- [ ] Draft value proposition statement
- [ ] Validate value prop with target customers (informal)

### Messaging Architecture
- [ ] Create launch headline/tagline
- [ ] Develop key talking points (5-7 main points)
- [ ] Write elevator pitch (30 seconds)
- [ ] Document FAQ with answers
- [ ] Create feature/benefit mapping
- [ ] Develop use case stories (3-5 use cases)

### Audience Segmentation & Messaging
- [ ] Identify primary audience segments (3-5)
- [ ] Define segment-specific pain points
- [ ] Tailor messaging for each segment
- [ ] Create persona-specific talking points
- [ ] Document segment priorities and sequencing
- [ ] Plan segment-specific content and campaigns

### Positioning Statement
- [ ] Draft positioning statement: "For [audience], [product] is [category] that [benefit]. Unlike [competition], [key differentiator]"
- [ ] Validate positioning with 3-5 customers
- [ ] Refine based on feedback
- [ ] Get leadership approval
- [ ] Document positioning rationale

### Proof Points & Social Proof
- [ ] Identify early customer testimonials/advocates
- [ ] Document customer success metrics/impact
- [ ] Gather customer quotes
- [ ] Plan case study interviews
- [ ] Identify analyst/expert validation opportunities
- [ ] Document market trends supporting product

---

## WEEK 3: Go-to-Market Strategy

### GTM Channel Strategy
- [ ] Identify primary GTM channels (owned, earned, paid, sales)
- [ ] Allocate budget across channels
- [ ] Define success metrics for each channel
- [ ] Establish channel owners and teams
- [ ] Create channel-specific tactics
- [ ] Document channel sequencing and timing

### Marketing Campaign Plan
- [ ] Create overall marketing campaign roadmap
- [ ] Plan blog post/content strategy
- [ ] Design landing page structure
- [ ] Plan email campaign sequence
- [ ] Create social media content calendar
- [ ] Plan paid advertising (search, display, social)
- [ ] Schedule all campaigns and content

### Sales Enablement Plan
- [ ] Create sales training agenda
- [ ] Develop sales collateral (one-pagers, decks)
- [ ] Build demo environment
- [ ] Create sales email templates
- [ ] Plan sales incentives/competition (if applicable)
- [ ] Schedule sales training sessions

### PR & Media Strategy (Tier 1/2)
- [ ] Identify key media outlets (20-30)
- [ ] Create media contact list
- [ ] Draft press release
- [ ] Plan media pitch strategy
- [ ] Schedule media preview calls
- [ ] Identify potential exclusive opportunities

### Customer Success Plan
- [ ] Create customer success playbook
- [ ] Define onboarding flow for new customers
- [ ] Plan customer education (webinars, docs)
- [ ] Create customer success KPIs
- [ ] Develop customer health monitoring
- [ ] Plan customer success team training

### Launch Events & Webinars
- [ ] Decide on launch events (webinar, livestream, etc.)
- [ ] Select date/time (global friendly)
- [ ] Plan event agenda and speakers
- [ ] Create event registration page
- [ ] Plan event promotion strategy
- [ ] Prepare event materials

---

## WEEK 4: Product Readiness

### Product Development Status
- [ ] Confirm feature development complete
- [ ] Verify all features working as designed
- [ ] Get product management sign-off
- [ ] Document product scope and features
- [ ] Create feature documentation
- [ ] Prepare release notes draft

### Quality Assurance & Testing
- [ ] Complete QA testing across browsers/devices
- [ ] Conduct accessibility testing (WCAG 2.1 AA)
- [ ] Perform security testing
- [ ] Execute performance/load testing
- [ ] Test all integrations and API connections
- [ ] Document and fix critical issues

### Analytics & Instrumentation
- [ ] Instrument all key events for tracking
- [ ] Set up conversion funnels
- [ ] Create launch measurement dashboard
- [ ] Set up custom dashboards for teams
- [ ] Verify analytics data flowing correctly
- [ ] Test all tracking in staging environment

### Error Monitoring & Alerting
- [ ] Set up error tracking (Sentry, Bugsnag, etc.)
- [ ] Create alerts for critical errors
- [ ] Set up performance monitoring
- [ ] Configure uptime monitoring
- [ ] Create on-call procedures
- [ ] Document escalation processes

### Security & Compliance
- [ ] Complete security review/penetration testing
- [ ] Verify data encryption (in transit, at rest)
- [ ] Confirm GDPR/CCPA compliance (if applicable)
- [ ] Review audit logging and data retention
- [ ] Document security features and capabilities
- [ ] Get security sign-off from InfoSec team

### Performance Optimization
- [ ] Verify page load times acceptable
- [ ] Optimize images and assets
- [ ] Test CDN performance
- [ ] Optimize database queries
- [ ] Configure caching appropriately
- [ ] Stress test at expected load

### Rollback & Contingency
- [ ] Document rollback procedures
- [ ] Create runbooks for common issues
- [ ] Set up feature flags for kill switches
- [ ] Plan phased rollout if needed
- [ ] Document manual rollback steps
- [ ] Test rollback procedure in staging

---

## WEEK 5: Beta Program Execution

### Beta Planning
- [ ] Finalize beta tier type (closed, open, invite-only)
- [ ] Set beta duration (2-4 weeks typical)
- [ ] Define beta success criteria
- [ ] Create beta communication plan
- [ ] Establish beta feedback process
- [ ] Plan beta retrospective

### Beta Recruitment
- [ ] Identify and recruit beta participants (20-50)
- [ ] Send beta invitations and onboarding
- [ ] Collect beta participant background info
- [ ] Set expectations for feedback and communication
- [ ] Create dedicated beta support channel
- [ ] Schedule kickoff call with beta group

### Beta Execution
- [ ] Monitor beta adoption and usage
- [ ] Collect feedback via surveys
- [ ] Conduct 1-on-1 customer interviews (5-10)
- [ ] Log and prioritize issues
- [ ] Fix critical bugs discovered in beta
- [ ] Gather testimonials from beta participants
- [ ] Track beta cohort metrics (adoption, retention)

### Beta Feedback Synthesis
- [ ] Aggregate feedback by theme
- [ ] Prioritize improvements based on impact
- [ ] Identify critical blockers vs. nice-to-haves
- [ ] Create improvement backlog
- [ ] Ship high-impact improvements
- [ ] Document learnings

### Preparation for General Release
- [ ] Communicate improvements made based on beta feedback
- [ ] Identify champion beta customers for launch
- [ ] Plan customer reference calls
- [ ] Prepare beta testimonials for launch
- [ ] Brief beta group on public launch date
- [ ] Thank and recognize beta participants

---

- [ ] Design email templates

- [ ] Create subject lines and preview text

### Social Media Strategy

- [ ] Design social graphics
- [ ] Plan influencer partnerships/mentions
- [ ] Set up hashtags and tagging strategy
- [ ] Schedule posts on platform

### Press Materials
- [ ] Write press release (500-750 words)
- [ ] Create media kit (if Tier 1)
- [ ] Compile media contact list (50-100)
- [ ] Create press preview presentation
- [ ] Identify exclusive opportunities
- [ ] Plan media outreach strategy

### Sales Materials
- [ ] Create one-page feature overview
- [ ] Develop sales presentation (15-20 slides)
- [ ] Create competitive comparison slide
- [ ] Write sales email template
- [ ] Build demo environment
- [ ] Create customer success playbook
- [ ] Create pricing one-pager (if applicable)

## WEEK 7: Launch Preparation & Rehearsal

### Cross-Functional Alignment
- [ ] Conduct launch readiness meeting
- [ ] Review launch plan with all teams
- [ ] Confirm ownership and responsibilities
- [ ] Review escalation procedures
- [ ] Verify all systems and tools ready
- [ ] Do final dry run of launch

### Launch Day Logistics
- [ ] Confirm launch date and time
- [ ] Schedule launch standups (6am, 12pm, 6pm)
- [ ] Set up launch monitoring dashboard
- [ ] Brief all team members on launch roles
- [ ] Create launch day communication templates
- [ ] Prepare "go/no-go" decision document

### Monitoring & Support Setup
- [ ] Set up monitoring dashboard
- [ ] Configure real-time alerts
- [ ] Assign monitoring responsibilities
- [ ] Create incident response procedures
- [ ] Brief support team on expected volume
- [ ] Set up support war room communication

### Launch Communications
- [ ] Prepare internal announcement email
- [ ] Create customer communication email
- [ ] Prepare social media posts (scheduled)
- [ ] Write internal Slack announcement
- [ ] Create all customer-facing messaging
- [ ] Prepare customer success briefing

### Team Training & Briefing
- [ ] Conduct full team briefing on launch
- [ ] Review launch goals and metrics
- [ ] Role-play launch scenarios
- [ ] Brief customer-facing teams
- [ ] Prepare support team for questions
- [ ] Share all launch materials with teams

### Final QA & Testing
- [ ] Conduct final product testing
- [ ] Test all CTAs and tracking
- [ ] Verify email campaigns are scheduled correctly
- [ ] Check landing page functionality
- [ ] Verify monitoring systems working
- [ ] Test rollback procedures one final time

## WEEK 8: Launch Execution & Measurement

### Launch Day (Morning Before Launch)
- [ ] Final team huddle (1 hour before launch)
- [ ] Check all systems are functioning
- [ ] Verify monitoring dashboard ready
- [ ] Brief executive team
- [ ] Final go/no-go decision
- [ ] Prepare to flip switch

### Launch Day (0-4 Hours)
- [ ] Execute launch/flip feature flag
- [ ] Publish blog post
- [ ] Send announcement email
- [ ] Post on social media
- [ ] Brief press (if press launch)
- [ ] Share internal announcement
- [ ] Monitor metrics closely (15-min cadence)

### Launch Day (4-24 Hours)
- [ ] Update leadership hourly on metrics
- [ ] Respond to initial customer feedback
- [ ] Address any critical issues immediately
- [ ] Share momentum internally
- [ ] Monitor support volume and sentiment
- [ ] Gather early feedback quotes

### Week 1 Measurements
- [ ] Track adoption rate vs. goal
- [ ] Measure awareness and reach
- [ ] Monitor customer sentiment (NPS, reviews)
- [ ] Analyze traffic and conversion
- [ ] Review customer feedback themes
- [ ] Monitor technical health (errors, performance)
- [ ] Brief leadership on week 1 results

### Week 1 Iteration
- [ ] Identify high-impact improvements
- [ ] Prioritize and ship fixes
- [ ] Respond to top feature requests
- [ ] Refine onboarding if needed
- [ ] Gather customer testimonials
- [ ] Document customer success stories

### Post-Launch Communication
- [ ] Publish customer testimonials/case studies
- [ ] Follow up with customers who tried feature
- [ ] Share success stories internally
- [ ] Continue social media engagement
- [ ] Respond to all customer questions/feedback
- [ ] Identify expansion opportunities

### Weeks 2-4 Activities
- [ ] Continue measuring key metrics
- [ ] Ship improvements based on feedback
- [ ] Conduct customer interviews (10-15)
- [ ] Analyze retention and usage patterns
- [ ] Optimize for growth/adoption
- [ ] Document learnings and insights

### Weeks 4-8 Activities
- [ ] Measure impact on North Star metric
- [ ] Analyze business impact (revenue, retention)
- [ ] Complete in-depth customer analysis
- [ ] Plan next phase of improvements
- [ ] Prepare launch retrospective
- [ ] Document success stories

## Launch Retrospective (Week 8)

### What Went Well?
- [ ] Celebrate team accomplishments
- [ ] Document successful tactics and strategies
- [ ] Identify team members who went above and beyond
- [ ] Identify processes to repeat in future launches

### What Could Be Better?
- [ ] Identify bottlenecks and delays
- [ ] Document what would help next time
- [ ] Identify communication gaps
- [ ] Review timeline and resource allocation

### Key Metrics vs. Goals
- [ ] Did we hit adoption target?
- [ ] Were awareness/reach goals met?
- [ ] Did we achieve revenue impact goals?
- [ ] Customer satisfaction goals achieved?
- [ ] Team satisfaction and sustainability?

### Deliverables for Next Launch
- [ ] Updated launch playbook/checklist
- [ ] Process improvements documentation
- [ ] Team feedback and suggestions
- [ ] Launch template updates
- [ ] Resource allocation recommendations

## Tier 3 Launch Simplified Checklist

For Tier 3 minor updates, use this simplified checklist:

**2 Weeks Before**:
- [ ] Finalize feature and confirm ready for launch
- [ ] Brief support team on feature
- [ ] Write help article/documentation
- [ ] Create release notes

**1 Week Before**:
- [ ] Create tooltip/banner text (if visual change)
- [ ] Test feature in production environment
- [ ] Prepare FAQ if needed
- [ ] Brief customer success team

**Launch Day**:
- [ ] Deploy feature
- [ ] Activate in-app messaging (if applicable)
- [ ] Monitor for critical issues
- [ ] Share release notes

**Post-Launch**:
- [ ] Monitor for user issues
- [ ] Respond to questions
- [ ] Track feature adoption
- [ ] Plan next improvement

## Common Pitfalls to Avoid

- **Starting too late**: Begin planning 8 weeks before target launch
- **Incomplete product**: Launching with known critical bugs
- **Unprepared teams**: Support/sales surprised by launch
- **No measurement**: Unable to assess launch success
- **Over-tiering**: Tier 3 update getting Tier 1 effort
- **Under-tiering**: Tier 2 feature getting Tier 3 resources
- **Poor communication**: Teams not knowing goals/timelines
- **Skipping beta**: Launching without customer validation
- **Missing retrospective**: Not capturing learnings for next launch
- **No contingency**: No plan if something goes wrong
