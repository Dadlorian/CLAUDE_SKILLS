Style Guide Overview

This interactive dashboard provides comprehensive guidance on maintaining consistent, high-quality technical documentation. Our style guide emphasizes clarity, accuracy, and accessibility.

Core Principles

  • Clarity: Write clearly and concisely for your audience
  • Consistency: Use uniform terminology and formatting throughout
  • Accuracy: Verify all technical information and examples
  • Accessibility: Ensure documentation is usable by all readers
  • Completeness: Provide all necessary information without ambiguity

Voice & Tone Guidelines

Consistent voice and tone make documentation more readable and professional. Our style emphasizes clarity and directness.

Active Voice

Always prefer active voice over passive voice. Active voice is more direct, engaging, and easier to understand.

❌ Passive Voice (Avoid)
The configuration is managed by the system administrator. The file was deleted by the user.
✓ Active Voice (Preferred)
The system administrator manages the configuration. The user deleted the file.

Formal Tone

Maintain a professional, formal tone. Avoid contractions and casual language.

❌ Casual (Avoid)
You can't modify this setting, but don't worry—it's not a big deal. We've added a bunch of new features that'll make your life easier.
✓ Formal (Preferred)
You cannot modify this setting. This is expected behavior. We have added several new features that improve usability.

Second Person Perspective

Address the reader directly using "you" when providing instructions.

✓ Second Person (Preferred)
To configure the system: 1. Open the settings menu. 2. Select your preferences. 3. Click Save.

Terminology Consistency

Use consistent terminology throughout your documentation. Pick one term and stick with it.

Term Preferred Avoid
User interface user-facing user facing, user interface
Backend backend back-end, back end
Frontend frontend front-end, front end
Email email e-mail, E-mail
API (first use) API (Application Programming Interface) API without definition

Document Structure

Well-organized documents are easier to read and navigate. Follow this structure for consistency.

Heading Hierarchy

Use proper heading levels to create a logical structure. Every document should start with a single H1 heading.

✓ Proper Heading Hierarchy
# Main Topic (H1) ## Section (H2) ### Subsection (H3) #### Details (H4)

Heading Capitalization

Use Title Case for all headings. Capitalize the first and last words, plus all major words.

❌ Incorrect Capitalization
## getting started with configuration ## installation and setup instructions ## understanding the api
✓ Proper Title Case
## Getting Started With Configuration ## Installation and Setup Instructions ## Understanding The API

Paragraph Length

Keep paragraphs short and focused. Aim for 3-4 sentences per paragraph.

❌ Too Long
The configuration system, which was originally designed for simple use cases but has evolved significantly over time, now supports an incredibly wide variety of scenarios including multiple data types, complex validation rules, nested structures, and seamless integration with external systems, all managed through a comprehensive yet user-friendly interface that attempts to balance functionality with ease of use while maintaining backward compatibility with existing configurations.
✓ Well-Organized
The configuration system is comprehensive and flexible. It supports multiple data types, complex validation rules, and nested structures. It also integrates seamlessly with external systems. The interface is designed for both power users and beginners. It maintains backward compatibility with existing configurations.

Lists and Formatting

Bulleted Lists

Use bulleted lists for items without a specific order. Keep list items grammatically parallel.

✓ Good List Format
Key features include: - Easy configuration - Flexible data types - Comprehensive documentation - Excellent performance

Numbered Lists

Use numbered lists for procedures or steps that must be followed in order.

✓ Proper Procedure Format
To install the software: 1. Download the installer 2. Run the installation wizard 3. Follow the on-screen prompts 4. Restart your system

Formatting Conventions

Consistent formatting improves readability and professionalism.

Code Formatting

Format code references appropriately in text:

Element Format Example
Inline code `code` Use the `npm install` command
File names `filename.ext` Edit the `config.json` file
Directories `/path/to/dir` Navigate to `/src/config`
Functions `functionName()` Call `initialize()`
Variables `variableName` Set `MAX_SIZE` to 1024

Code Blocks

Use fenced code blocks with language specification:

✓ Proper Code Block
```javascript function example() { return "Hello, World!"; } ```

Emphasis

Use emphasis sparingly for clarity, not style:

Emphasis Type Markdown Use Case
Bold **text** Important terms, warnings
Italic *text* Book titles, emphasis
Code `text` Code references

Numbers and Units

Format numbers consistently throughout documentation:

✓ Proper Number Formatting
- Use 512 MB minimum - Process 100,000+ records - Configure 0x1F values - Wait 5 seconds (not 5 secs)

Common Writing Issues

These are the most frequently encountered problems in technical documentation.

1. Unexplained Jargon

Define technical terms on first use, especially for new readers.

❌ Undefined Jargon
The API uses OAuth for authentication. The REST endpoint returns JSON data.
✓ Defined Terms
The API (Application Programming Interface) uses OAuth, an authentication protocol, for security. The REST (Representational State Transfer) endpoint returns JSON (JavaScript Object Notation) data.

2. Weak Phrases

Replace clichés with specific, direct language:

Weak Strong
a lot of users many users
in order to to
take into account consider
it goes without saying [delete or rephrase]

3. Inconsistent Terminology

Don't use different terms for the same concept. Pick one and use it consistently:

❌ Inconsistent
The user-facing component displays data. The client side validation works well. The front end interface is clean.
✓ Consistent
The user-facing component displays data. The client-side validation works well. The frontend interface is clean.

4. Missing Acronym Definitions

Always define acronyms on first use:

❌ Undefined
Configure the API endpoint. Enable HTTPS for security.
✓ Defined
Configure the API (Application Programming Interface) endpoint. Enable HTTPS (Hypertext Transfer Protocol Secure) for security.

5. Outdated or Problematic Terms

Use modern, inclusive terminology:

❌ Deprecated
Add the IP to the whitelist. Configure the master database. Perform a sanity check.
✓ Inclusive
Add the IP to the allowlist. Configure the primary database. Perform a verification check.

  • All sentences use active voice
  • No contractions in formal writing
  • All acronyms are defined on first use
  • Headings use Title Case
  • Code is formatted with backticks
  • Lists use consistent formatting
  • Terminology is consistent throughout
  • No deprecated or problematic terms
  • Paragraphs are focused and concise
  • Links are valid and working

Pre-Submission Checklist

Use this checklist before submitting your documentation for review.

Content Review

  • Information is accurate and current
  • All examples are tested and correct
  • Code samples follow coding standards
  • No broken links or references
  • All URLs are valid and updated
  • Images have descriptive alt text

Style and Tone

  • Writing uses active voice throughout
  • No contractions in formal sections
  • Tone is professional and consistent
  • Audience is clearly identified
  • Technical level is appropriate
  • Jargon is explained adequately

Formatting and Structure

  • Document has clear hierarchy with H1 heading
  • All headings use proper Title Case
  • Lists are consistent (bullets or numbers)
  • No trailing whitespace
  • Code blocks have language specified
  • Tables are properly formatted

Technical Writing

  • Acronyms defined on first use
  • Terminology is consistent
  • No deprecated terms used
  • Numbers formatted consistently
  • File paths and commands are clear
  • Procedures are in logical order

Automated Checks

  • Vale style check passes (no errors)
  • Markdown lint passes
  • Spell check passes
  • Link validation passes
  • No console warnings or errors
  • Pre-commit hooks pass successfully
