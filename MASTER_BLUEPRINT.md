## Standard Folder Structure

Each domain follows this structure:

```
XX_domain_name/
├── skill.md                    # Domain definition
├── README.md                   # Domain overview
├── instruction.md              # AUTO-GENERATION SCRIPT
├── standards/
│   ├── style-guides/          # Writing, naming, documentation standards
│   ├── api-guides/            # API design, integration patterns
│   ├── legacy-integration-guides/  # Migration, compatibility
│   ├── evidence/              # Research, benchmarks, whitepapers
│   └── patterns/              # Domain-specific patterns
└── skills/
    ├── 01_subskill_name/
    │   ├── skill.md
    │   ├── instruction.md     # Subskill auto-generation
    │   ├── reference/         # Quick reference materials
    │   ├── guides/            # Step-by-step guides
    │   └── src/               # Code examples, templates
    ├── 02_subskill_name/
    └── ... (10 subskills per domain)
```

## Execution Strategy

### Parallel Domain Creation
1. Open 32 browser tabs (one per domain)
2. Each tab runs: `instruction.md` in that domain folder
3. Claude generates all domain-specific content
4. Each domain independently creates its 10 subskills

### Generation Flow
```
ROOT/instruction.md
  ↓ generates →  global_standards/

XX_domain/instruction.md
  ↓ generates →  skill.md, README.md, standards/
  ↓ triggers →   skills/*/instruction.md

skills/XX_subskill/instruction.md
  ↓ generates →  skill.md, reference/, guides/, src/
```
